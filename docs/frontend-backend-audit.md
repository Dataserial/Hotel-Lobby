# ผลตรวจ frontend และ backend

ตรวจจากโค้ดใน workspace และทดสอบกับฐานข้อมูล MongoDB replica set สำหรับทดสอบโดยเฉพาะ ไม่ได้ใช้หรือแก้ข้อมูลการจองบนระบบออนไลน์

## จุดที่พบและแก้แล้ว

| เรื่อง | สิ่งที่พบก่อนแก้ | ผลหลังแก้ |
|---|---|---|
| สิทธิ์ผู้ดูแลระบบ | เปลี่ยน admin ของตัวเองเป็น customer ผ่าน API ได้ และทำให้เหลือ admin 0 คน | ห้ามลดสิทธิ์ตัวเองไปทุก role ที่ไม่ใช่ admin และยังใช้ guard ป้องกันการลดสิทธิ์พร้อมกัน |
| เซสชัน | คำตอบ 401 ของคำขอเก่าทำให้บัญชีที่ล็อกอินใหม่หลุดได้ | ตรวจ token ของเซสชันต้นทางก่อนล้างบัญชีปัจจุบัน |
| ข้อมูลบริการเพิ่มเติม | frontend ยอมรับ JSON ของบริการที่ขาดชื่อ ราคา หรือเงื่อนไขสำคัญ | ตรวจ schema ของราคา หน่วยคิดราคา จำนวนสูงสุด สถานะ และ pagination ก่อนนำมาแสดง |
| จัดการบริการเพิ่มเติม | backend สร้างบริการและแก้เงื่อนไขได้ แต่หน้าจอมีเฉพาะราคา/เปิดปิด และอ่านเพียง 100 รายการแรก | เพิ่มสร้าง/แก้ชื่อ หน่วย ราคา รวมในค่าห้อง เตียงเสริม ประเภทห้อง จำนวนสูงสุด สถานะ ค้นหา และแบ่งหน้า |
| ความสัมพันธ์บริการกับประเภทห้อง | บริการอ้างอิงประเภทห้องที่ไม่มีจริงได้ และลบประเภทห้องที่บริการยังอ้างอิงได้ | ตรวจประเภทห้องที่อ้างอิง และปฏิเสธการลบประเภทที่ยังมีบริการหรือห้องใช้อยู่ |
| เตียงเสริม | schema มี supportsExtraBed แต่ room-type CRUD และหน้าจอไม่ได้เปิดให้ตั้งค่า | เพิ่มตั้งค่าการรองรับเตียงเสริมทั้ง API และหน้าจอประเภทห้อง |
| ค้นหาการจอง | backend กรองผู้พัก ห้อง วันเข้า วันออกได้ แต่หน้าจอมีเฉพาะสถานะ | เพิ่มตัวกรองและตัวเลือกผู้พัก/ห้องที่ค้นหาและแบ่งหน้าได้ พร้อมปุ่มล้างตัวกรอง |
| เวลาเข้าพักจริง | API มี actualCheckInAt / actualCheckOutAt / cancelledAt แต่รายละเอียดแสดงเฉพาะวันตามกำหนด | แสดงเวลาเข้าจริง ออกจริง และเวลายกเลิกตามเวลาไทย |
| ผู้เข้าพัก | backend รองรับ active และค้นหาเลขเอกสารตรงกัน แต่ไม่มีตัวควบคุมในหน้าจอ | เพิ่มเก็บถาวร/เปิดกลับ กรองสถานะ และค้นหาด้วยเลขเอกสาร โดยรักษาประวัติการจอง |
| ห้องและประเภทห้อง | backend มีตัวกรองและลบรายการที่ไม่มีประวัติ แต่หน้าจอยังใช้ไม่ครบ | เพิ่มตัวกรองสถานะ/ประเภท/การเปิดใช้ และปุ่มลบสำหรับ admin พร้อมยืนยันและใช้ข้อจำกัด backend |
| ผู้ใช้งาน | backend กรอง role และ active ได้ แต่หน้าจอมีเฉพาะค้นหา | เพิ่มตัวกรองสิทธิ์และสถานะบัญชี |
| การรับเงินบางส่วน | backend รับยอดจำนวนเต็มที่ไม่เกินคงเหลือได้ แต่ dropdown จำกัดเฉพาะราคาเป็นคืน | คงตัวเลือกตามราคาห้อง และเพิ่ม “ระบุยอดรับจริงอื่น ๆ” พร้อมตรวจยอดก่อนส่ง |
| ข้อความภาษาไทย | ข้อผิดพลาดการเปลี่ยนสถานะ/อ้างอิง/ยอดเงินหลายกรณีขึ้นอังกฤษ | เพิ่มคำอธิบายไทยของข้อผิดพลาดที่ใช้ในหน้าจอเหล่านี้ |
| คู่มือการจอง | หน้าแรกและหน้าเข้าสู่ระบบยังอธิบายให้ติดต่อพนักงานเพื่อยืนยัน | ปรับให้ตรงกับเลือกวัน → ประเภท → เลขห้อง → เข้าบัญชีและยืนยันจอง → ชำระที่โรงแรม |
| บริการฝั่งลูกค้า | มี API สาธารณะรายการบริการ แต่ flow จองใหม่ไม่ได้แสดง | เพิ่มรายการบริการในหน้าสรุปจอง อ่านครบทุกหน้า แยกรวมในค่าห้อง/รอยืนยันราคา และซ่อนเตียงเสริมที่ประเภทห้องไม่รองรับ |
| ช่องทางติดต่อ | หน้าบัญชีบอกให้ติดต่อเพื่อแก้ไข/ยกเลิก แต่ไม่มีช่องทางในหน้านั้น | เพิ่มช่องทางจาก VITE_CONTACT_PHONE / EMAIL / URL ที่ตรวจรูปแบบแล้ว และข้อความเมื่อยังไม่ได้ตั้งค่า |

## ขอบเขตที่ต้องรู้

- การจองลูกค้ารองรับสร้างและดูประวัติ การแก้ไข/ยกเลิกยังให้พนักงานดำเนินการตาม API และสิทธิ์ที่มีอยู่ จึงไม่ได้เพิ่ม endpoint ของลูกค้าโดยเลี่ยงเงื่อนไขคืนเงิน
- บริการเพิ่มเติมแสดงข้อมูลและเงื่อนไขได้ การเพิ่มบริการเข้าการจองโดยตรงและคิดรวมกับ payment ledger ยังไม่มีใน customer-booking API จึงไม่สร้างปุ่มซื้อที่ส่งข้อมูลไม่ได้ หรือรวมราคาบริการเข้ายอดห้องโดยไม่มี snapshot รองรับ
- รายงาน backend ปัจจุบันเป็นยอด ledger ตลอดเวลา การเลือกช่วงวันและ export รายงานต้องเพิ่ม backend สำหรับรายงานนั้นก่อน
- `/stay-requests` และองค์ประกอบ flow เก่ายังอยู่เพื่อรองรับข้อมูลเดิม แต่เมนูพนักงานที่ผู้ใช้ขอเอาออกไม่ได้ถูกนำกลับมา
- ช่องทางติดต่อจริงต้องใช้ข้อมูลที่โรงแรมยืนยันแล้ว หาก VITE_CONTACT_* ว่าง จะแสดงว่าช่องทางออนไลน์ยังไม่พร้อม ไม่มีเบอร์หรือ URL ที่แต่งขึ้น
- การเปลี่ยนแปลงยังไม่ได้ deploy ไป Vercel/Render

## Prompt AI สำหรับงานที่ตรวจและใช้แก้แล้ว

### 1. สิทธิ์ admin และเซสชัน

```text
ตรวจและแก้ server/routes/api-users.js ให้ active admin เปลี่ยน role ตัวเองไป receptionist หรือ customer ไม่ได้ และห้ามระบบเหลือ active admin 0 คนแม้มีการเปลี่ยนพร้อมกัน ใช้ transaction และ shared admin guard เดิม เพิ่ม regression tests ผ่าน HTTP กับ MongoDB ทดสอบ

แก้ client/src/App.tsx ให้คำตอบ 401 หรือ timer จาก token เก่าไม่ล้างเซสชันที่ล็อกอินใหม่ รักษาการหมดอายุและ logout ของ token ปัจจุบัน ทดสอบ logout แล้ว login บัญชีใหม่ก่อนให้คำขอเก่าตอบ 401
```

### 2. บริการเพิ่มเติม

```text
เติมหน้าจอ AdditionalServices ให้ใช้ POST/PATCH/GET ของ backend ครบ: ชื่อ หน่วย ราคา nullable included extraBed roomTypeIds maxQuantity active ค้นหาและแบ่งหน้า อย่าจำกัดที่ 100 รายการแรก ตรวจ response schema และแสดง loading/error/success ตรวจชนิดห้องที่อ้างอิงใน backend และห้ามลบประเภทห้องที่ยังถูกอ้างอิง เพิ่ม supportsExtraBed ใน room-type API และฟอร์มโดยไม่เปลี่ยน schema ที่มีอยู่แล้ว

แสดงรายการบริการสาธารณะในหน้าสรุปจอง อ่านครบ pagination และกรองเตียงเสริมตามประเภทห้อง ระบุให้ชัดว่าบริการที่คิดเพิ่มยังไม่รวมในยอดจองห้อง จนกว่าจะมี backend snapshot สำหรับบริการในการจองโดยตรง
```

### 3. หน้าจอจัดการที่ backend รองรับแล้ว

```text
เทียบ API กับหน้าพนักงาน เติมตัวกรองที่ backend มีอยู่ใน bookings, rooms, room-types, guests และ users ใช้ picker/pagination ที่เข้าถึงรายการเกินหน้าแรกได้ เพิ่มเก็บผู้พักถาวร/เปิดกลับด้วย PATCH active โดยไม่ลบประวัติ เพิ่มปุ่มลบห้องและประเภทห้องเฉพาะ admin และให้ backend ปฏิเสธรายการที่มีประวัติหรืออ้างอิง แสดงเวลา actualCheckInAt/actualCheckOutAt/cancelledAt ตาม Asia/Bangkok ทดสอบการกดหน้าจอกับ backend จริง
```

### 4. การรับเงินและข้อความการใช้งาน

```text
คง dropdown จำนวนเงินตามราคาเดิมของการจอง เพิ่มระบุยอดรับจริงสำหรับ partial payment ตรวจ integer baht >0 และไม่เกิน remaining รักษา idempotency และป้องกันการรับซ้ำ แปล error codes ของ state/reference/payment/admin เป็นไทย ปรับคู่มือหน้าแรกและหน้า login ให้ตรงกับ flow จองจริง เพิ่มช่องทางติดต่อโรงแรมจาก config ที่ยืนยันแล้วพร้อม fallback เมื่อยังไม่ได้ตั้งค่า
```

## การตรวจสอบ

ผลล่าสุด: frontend 69 tests และ backend 235 tests ผ่านทั้งหมด รวม 304 tests; frontend build/lint และ backend lint ผ่าน

- Frontend: `npm run build`, `npm run lint`, `npm test`
- Backend: `npm run lint`, `npm run test:all:isolated`
- มี regression tests สำหรับ admin demotion, stale 401, malformed service data, partial receipt, public catalog และการกดหน้าจอ admin/receptionist กับ HTTP และฐานข้อมูลจริง
- ทดสอบบริการ 101 รายการเพื่อยืนยันว่าเข้าถึงหน้าถัดไปได้ และทดสอบเก็บผู้เข้าพักโดยประวัติการจองยังอยู่
