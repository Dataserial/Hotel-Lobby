# ข้อมูลที่ต้องเติมและประเด็นที่ต้องยืนยันก่อนส่งรายงาน

ไฟล์รายงาน `hotel_management_project_proposal.docx` และ `hotel_management_project_proposal.pdf` เป็น **เค้าโครงโครงงาน** ตามรูปแบบไฟล์ตัวอย่าง ข้อมูลระบบมาจากไฟล์แผนพัฒนา Web App ระบบจัดการห้องโรงแรมที่แนบมา เอกสารแผนเป็นข้อเสนอและรายการงาน จึงยังใช้แทนหลักฐานว่าพัฒนาหรือทดสอบสำเร็จไม่ได้

## 1. ข้อมูลสำหรับหน้าปกและหน้าเสนอเค้าโครง

- [ ] กรอกชื่อและรหัสนักศึกษาของสมาชิกทั้ง 5 คน ตรวจสะกดชื่อภาษาไทย/อังกฤษหากสถาบันกำหนด
- [ ] กรอกชื่อ ตำแหน่ง และคำนำหน้าอาจารย์ที่ปรึกษา
- [ ] กรอกรหัสวิชา ชื่อวิชา ภาคเรียน ปีการศึกษา สาขาวิชา คณะ/วิทยาลัย และมหาวิทยาลัย
- [ ] ยืนยันชื่อหัวข้อภาษาไทยและภาษาอังกฤษอย่างเป็นทางการ รวมถึงเดือน/ปีบนหน้าปก
- [ ] กรอกสถานที่ดำเนินงานและโรงแรมกรณีศึกษาในหัวข้อ 7 หรือระบุอย่างชัดเจนว่าใช้ข้อมูลจำลอง
- [ ] ตรวจและลงนามผู้จัดทำกับอาจารย์ที่ปรึกษาในหน้าสุดท้ายเมื่อพร้อมส่ง

## 2. ขอบเขตและการตัดสินใจทางเทคนิค

- [ ] **ระยะเวลาไม่ตรงกัน:** แผนต้นทางตั้งชื่อตารางว่า “1 สัปดาห์” แต่หัวข้อความเสี่ยงกล่าวถึง “6 สัปดาห์” ต้องกำหนดวันเริ่ม วันสิ้นสุด ระยะของแต่ละช่วง และวันที่ส่งงานจริง แล้วปรับหัวข้อ 9
- [ ] **ORM/ฐานข้อมูล:** แผนระบุ MongoDB Atlas + Mongoose และอีกจุดระบุ Prisma ORM ต้องเลือกชุดที่ใช้งานจริงและแก้หัวข้อ 5.2 ให้ตรงกัน
- [ ] **การยืนยันตัวตน:** แผนระบุ JWT ใน HttpOnly cookie, bcrypt และ Express Session เป็นทางเลือก ต้องเลือกวิธี session/token เพียงแนวทางที่พัฒนาจริง ระบุอายุ การออกจากระบบ และการป้องกัน CSRF ตามวิธีที่เลือก
- [ ] **สิทธิ์แก้ไขห้องพัก:** ตารางสิทธิ์ต้นทางเขียนว่า Receptionist ค้นหาห้องว่าง แต่ตาราง API เขียนว่าแก้ไข Rooms “ตาม permission” ต้องกำหนดว่าใครเพิ่ม/แก้ไข/ลบห้องและประเภทห้องได้
- [ ] **Public Availability API:** ต้องยืนยันว่าเปิดสาธารณะจริงหรือใช้ API key, กฎ rate limit, รายชื่อ origin ที่อนุญาต, รูปแบบ error และเวอร์ชันเส้นทาง `/api/public/rooms/availability`
- [ ] **กฎห้องว่าง:** ยืนยันว่าคำนวณจากการจองในช่วงวันที่ค้นหาอย่างไรเมื่อสถานะห้องเป็น `occupied` ในปัจจุบัน แต่วันที่ค้นหาเป็นอนาคต รวมถึงกฎห้อง `maintenance`
- [ ] **กฎชำระเงินและยกเลิก:** ระบุรายการสถานะ booking/payment ทั้งหมด เงื่อนไขเช็กอิน/เช็กเอาต์ การจ่ายบางส่วน การคืนเงินภายนอก และการยกเลิกหลังชำระเงิน
- [ ] **การป้องกันจองซ้อนพร้อมกัน:** เลือกวิธีบังคับความถูกต้องที่ฐานข้อมูล/บริการและทดสอบคำขอพร้อมกันจริง การตรวจช่วงวันที่ก่อนแสดงผลอย่างเดียวไม่เพียงพอ
- [ ] **ข้อมูลส่วนบุคคล:** ระบุข้อมูลเอกสารตัวตนที่จำเป็น ระยะเวลาเก็บ การจำกัดสิทธิ์ดู/ลบ/ปกปิด และรูปแบบข้อมูลจำลองสำหรับทดสอบ
- [ ] ยืนยันว่าขอบเขต MVP รวมการ “ดูรายงาน” ระดับใด เพราะเอกสารต้นทางระบุสิทธิ์ Admin แต่ยังไม่ให้รายการตัวชี้วัดหรือหน้ารายงานโดยละเอียด

## 3. หลักฐานที่ต้องเก็บหากจะเปลี่ยนเป็นรายงานผลการพัฒนา

- [ ] ลิงก์ repository, README, คู่มือรัน, สถาปัตยกรรม/ER หรือ Data Model และภาพหน้าจอระบบจริง
- [ ] รายชื่อเจ้าของงานและ reviewer ของแต่ละโมดูล พร้อมสถานะงานที่ตรวจรับแล้ว ไม่ใช้รายการ Step ในแผนเป็นหลักฐานว่างานเสร็จ
- [ ] ชุดทดสอบและผลจริงสำหรับ Login/Logout, บัญชีปิด, สิทธิ์ Admin/Receptionist, CRUD, การค้นหา, การจองวันติดกัน/ทับซ้อน และคำขอพร้อมกัน
- [ ] ผลทดสอบทุก transition ของ booking/room/payment รวมถึงการเช็กอินก่อนวันเข้าพัก ห้องไม่พร้อม ยอดค้าง และการยกเลิก/คืนเงิน
- [ ] Postman Collection หรือ API documentation พร้อมผลเรียก Public API จากภายนอก กรณีข้อมูลผิด และการตรวจว่าไม่เปิดเผยชื่อ เบอร์โทร หรือเลขเอกสารผู้เข้าพัก
- [ ] ผล System Test, Responsive Test, Security Checklist, บั๊กที่พบและผลทดสอบซ้ำหลังแก้ไข
- [ ] URL สาธิตหรือหลักฐาน deploy จริง และวันเวลาที่ตรวจสอบ หากยังไม่ deploy ให้ใช้คำว่า “แผนการนำขึ้นระบบ”
- [ ] หากจะอ้างประสิทธิภาพ ให้กำหนดสภาพแวดล้อม วิธีวัด จำนวนรอบทดสอบ และผลจริงก่อนสรุป

## 4. งบประมาณและเอกสารอ้างอิง

- [ ] กำหนดผู้ให้บริการโฮสต์/ฐานข้อมูล แพ็กเกจ ระยะเวลา ราคาแต่ละรายการ และยอดรวมในหัวข้อ 10 ห้ามนำตัวเลขของรายงานตัวอย่างมาใช้กับโครงงานนี้
- [ ] ตรวจรูปแบบบรรณานุกรมตามเกณฑ์รายวิชา และเติมปีพิมพ์/วันเข้าถึงของแหล่งเว็บหากสถาบันกำหนด
- [ ] ยืนยันผู้แต่งและปีของเอกสารแผนพัฒนาที่แนบมา หากมีข้อมูล เพื่อแก้รายการอ้างอิง [2]

## 5. วิธีปรับเอกสารหลังได้ข้อมูล

แก้ข้อมูลในไฟล์ `.docx` แล้วส่งออก PDF ฉบับใหม่ ตรวจหน้าเอกสารทุกหน้าหลังปรับ โดยเฉพาะหน้าปก ตาราง และหน้าลงนาม เมื่อมีหลักฐานผลพัฒนาจริงจึงเปลี่ยนถ้อยคำ “แผน/คาดว่าจะ” เป็น “ผลที่พบ” พร้อมตัวเลขและหลักฐานอ้างอิง
