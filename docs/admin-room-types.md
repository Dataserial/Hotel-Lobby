# การเพิ่มประเภทห้อง

Standard, Deluxe และ Family เป็นข้อมูลตั้งต้นใน `server/scripts/seed-rooms.js` ที่บันทึกเป็นเอกสารใน collection `roomTypes` ของ MongoDB ไม่ใช่ enum หรือรายการฟิกซ์ใน frontend ส่วน `seed-demo.js` สร้างชื่อ Demo Standard, Demo Deluxe และ Demo Family แยกต่างหาก

ระบบเดิมมี RoomType model, POST/PATCH API และหน้าจัดการประเภทห้องแล้ว การแก้ไขนี้เพิ่มปุ่ม **＋ เพิ่มประเภทห้อง** ในหน้า **ห้องพัก / ประเภท** ให้แอดมินเปิดฟอร์มสร้างได้ทันที ปรับชื่อปุ่มในหน้าจัดการให้ตรงกัน แสดงข้อผิดพลาดใน dialog จำกัดชื่อไม่เกิน 80 ตัวอักษร ปฏิเสธชื่อที่มีแต่ช่องว่าง และแสดงรายการที่บันทึกสำเร็จแม้ก่อนหน้าจะมีตัวกรองหรืออยู่หน้าอื่น

## วิธีใช้

1. เข้าสู่ระบบที่ `/staff` ด้วยบัญชี admin แล้วเลือก **ห้องพัก / ประเภท**
2. กด **＋ เพิ่มประเภทห้อง** ระบุชื่อ ความจุ 1–20 คน ราคาเต็มบาทตั้งแต่ 0 ถึง 2,147,483,647 และสิ่งอำนวยความสะดวกคั่นด้วยจุลภาค จากนั้นบันทึก
3. กลับหน้าห้องพัก แล้วเพิ่มหรือแก้ไขห้องพักเพื่อกำหนดประเภทใหม่ให้ห้องจริง
4. ประเภทใหม่จะปรากฏให้ลูกค้าตามข้อมูลห้องที่เปิดใช้งาน สถานะห้อง จำนวนผู้เข้าพัก และวันที่ค้นหา การสร้างประเภทอย่างเดียวไม่ได้สร้างห้องพักให้อัตโนมัติ

ตัวเลือกประเภทห้องของพนักงานโหลดจาก `/api/room-types` แบบแบ่งหน้าและค้นหา ส่วนหน้าลูกค้าโหลดข้อมูลจาก public APIs ซึ่งอ่านฐานข้อมูลอยู่แล้ว จึงไม่ต้องเพิ่มชื่อประเภทในโค้ด

## สิทธิ์และฐานข้อมูล

ใช้ backend เดิมที่ตรวจ session และอนุญาตเขียนประเภทห้องเฉพาะ admin; receptionist อ่านได้ ส่วน customer เข้า API ภายในนี้ไม่ได้ ตรวจจำนวนเต็ม ความยาว ข้อมูลซ้ำ และฟิลด์ที่อนุญาตบน server โดย `nameKey` มี unique index ป้องกันชื่อซ้ำโดยไม่แยกตัวพิมพ์ใหญ่เล็ก บันทึก createdById/updatedById จากผู้ใช้ที่เข้าสู่ระบบ

ไม่เปลี่ยน schema และไม่ต้อง migrate สำหรับฐานที่เตรียม schema/index ตามโครงการไว้แล้ว ไม่ได้ deploy หรือเชื่อมฐาน production
